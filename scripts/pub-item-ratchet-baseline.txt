# Number of `pub` items whose only consumer outside their defining file
# is test code, as measured by scripts/scan-pub-item-usage.py.
#
# Enforced by scripts/check-pub-item-ratchet.sh. This number must never
# go up. Lower it whenever a cleanup lands; the script tells you to.
#
# Measured on WOR-1941, 2026-07-30, after inbound key validation and
# key-plane generation pinning gained their production consumers.
#
# Raised to 216 on WOR-2098, 2026-07-31: the RAG provider adapters ship
# wire-contract integration tests, and their injection seams (scripted
# DNS resolver, address policy, fixture-pinned client builder, escape
# helper, render probe) must be `pub` for `tests/` to reach them. All
# are `#[doc(hidden)]` and most also have in-crate production callers.
#
# Raised to 218 on WOR-2099, 2026-07-31: the distributed semantic cache
# added `SemanticNamespace::origin_prefix` and
# `SEMANTIC_ANONYMOUS_CREDENTIAL`, both in sbproxy-ai and both consumed
# from sbproxy-core's test modules (the Redis purge-scope tests and the
# credential-identity tests). Cross-crate test use requires `pub`, so
# neither can be narrowed, and both have in-file production callers.
#
# Raised to 319 on WOR-2100, 2026-07-31: the whole delta is the new
# `sbproxy-billing` crate, and it is the one case this ratchet's fourth
# option was written for. The crate is the durable settlement domain,
# and its production caller does not exist yet: the `ai_crawl` policy
# still emits the legacy per-rail challenge and redeems against the old
# ledger, so nothing in the request path yet names a payment
# requirement, a rail adapter, or a settlement receipt. Its 224 tests
# are its only consumers today.
#
# These are not narrowable. The crate's public surface is what
# `sbproxy-core` will call across a crate boundary, and the contract
# tests that pin the wire formats (x402 v2, Payment Auth draft-01,
# Stripe PaymentIntents, CLN, LND) live in `tests/` precisely so they
# exercise the same surface a caller gets rather than a private one.
#
# This number comes back down when the origin gate lands and the
# request path starts calling the service, the registry, and the
# requirement types. Do not raise it again for this crate.
#
# Raised to 321 on WOR-2139, 2026-08-01, for two items that cannot be
# narrowed without defeating what they are for.
#
# `run_scoped_label_gaps` (sbproxy-observe/src/metric_registry.rs) is
# the static guard that forbids a run, task, context, or trace id from
# becoming a Prometheus label. Its consumer is
# `tests/metric_drift.rs`, a separate integration-test crate, so `pub`
# is the only way to reach it. `tenant_label_gaps` sits beside it for
# exactly the same reason and has since it was written. The guard has
# to run against the same public table a caller sees; asserting against
# a private copy would prove nothing.
#
# `MAX_RUN_ID_BYTES` (sbproxy-ai/src/tracing_spans.rs) is the cap
# applied to a caller-supplied run identifier before it reaches a span
# attribute. It crosses into sbproxy-core, where the body phase caps at
# capture so the span and the access log agree on one value. A cap that
# two crates must agree on is a contract, not an implementation detail.
#
# Lowered to 305 on WOR-2143, 2026-08-01: the settlement origin gate
# landed and the request path now calls the sbproxy-billing surface the
# WOR-2100 note promised a caller for. Sixteen items gained production
# consumers: the service (authorize, prepare_requirement, the decision
# and problem types), derive_intent_id, the requirement and proof types,
# the x402 challenge renderer and header codecs, the Payment Auth
# challenge binder and credential selector, and the CLN challenge
# fields.
#
# Raised to 314 on WOR-2081, 2026-08-01, and this one is a measurement
# correction rather than new write-only code. Deleting the unwired
# `sbproxy-cache/src/two_tier.rs` removed five candidates, but all five
# carried a recorded `escalated` verdict, so none of them were ever
# counted in this number. What the deletion did change is the textual
# match this scan is built on: `two_tier.rs` defined its own
# `with_threshold`, and because the scan counts an identifier as
# referenced when the word appears in any non-test file, that unrelated
# definition was standing in as a production reference for
# `prompt_injection_v2::with_threshold` in sbproxy-modules. Both of that
# item's real callers are inside `#[cfg(test)]` blocks
# (`prompt_injection_v2/mod.rs` and `body_aware.rs`), so it has been
# tests-only all along and the scan simply could not see it.
#
# The number going up here means the scan got more accurate, not that
# the workspace got worse. Narrowing that builder is a separate change
# against sbproxy-modules and is not bundled into a cache deletion.

# Lowered to 312 on WOR-2179 / WOR-2164, 2026-08-02, and this is another
