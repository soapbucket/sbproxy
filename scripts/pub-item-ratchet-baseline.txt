# Why this file has no number in it
#
# The count lives beside it in scripts/pub-item-ratchet-baseline.count,
# alone on the only line of that file. This file is the log of why the
# count moved, and nothing else. Both are read by
# scripts/check-pub-item-ratchet.sh.
#
# The split is a merge fix (WOR-2252). While the number sat on line 221
# of a 289-line file, two branches that both bumped it wrote to
# non-adjacent lines, git saw two independent hunks, and took both. The
# result was a baseline file holding two numbers, which the old reader
# squashed into one impossible integer like "287286": a ceiling no real
# count can exceed, so the check passes forever while silently handing
# back every narrowing anyone lands. This file has hit eight conflicts.
#
# A one-line file cannot merge that way. Two branches that both change
# the count change the same line, so git stops and asks. That is the
# entire point of the arrangement, and the answer to such a conflict is
# always to recompute against the merged tree
#
#   python3 scripts/scan-pub-item-usage.py --count tests-only
#
# and never to keep either side's number, because neither side's number
# describes the merge.
#
# The notes below are append-only and conflict freely, which is fine: a
# conflict in prose is resolved by keeping both paragraphs, and that is
# the right resolution for a log.
#
