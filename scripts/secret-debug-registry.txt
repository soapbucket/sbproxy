# Types that hold a reusable credential and must never derive `Debug`
# (WOR-2640). One entry per line:
#
#   <path> | <Type> | <test fn that pins it>
#
# `scripts/check-secret-debug-registry.sh` refuses a tree where any
# entry has regained `Debug` in its derive, lost its hand-written
# `impl std::fmt::Debug`, or lost the test that pushes a sentinel
# through it. There are no exemptions and there is no baseline count:
# every line here names a type somebody already decided a `{:?}` must
# not print, so a line going red means that decision was reversed.
#
# This list is append-only in practice. Removing a line is removing a
# protection, and the only honest reason to do it is that the type
# itself is gone.
#
# What this cannot see, said plainly because a guard trusted past its
# detector is worse than none: a *new* secret-bearing type that never
# gets a line here. Nothing derives the list from the code, because
# "this field holds a credential" is a judgment about meaning and not
# a pattern. Adding the line is part of adding the type.
#
# The rule is one rule; the mechanism is one hand-written `Debug` per
# type rather than one wrapper type. `docs/secrets.md`, under "Why the
# policy is one rule and not one type", gives the two constraints that
# make it so: `SecretString` has no serde impls and cannot be a config
# field type, and `sbproxy-vault` depends on `sbproxy-observe`, so the
# observe-side types cannot reach it at all.

# --- WOR-2661: the shared embedded store's credential-bearing types ---
# A subscription's HMAC secret cannot be a one-way hash, because the
# notifier re-derives a signature on every delivery, so the record holds
# it in the clear and only the `Debug` keeps it out of a log line. The
# registration secrets are returned once and never again. The ingest
# target holds a resolved broker token and warehouse password and is
# reachable from a line that describes boot.

# --- WOR-2566: the customer-managed root of trust ---
#
# Two config-side twins carrying the key service's token and its address
# (unparsed, so it may carry userinfo), the runtime client that holds the
# resolved token, and the two types that hold nothing but key material:
# the decrypted upstream credential and the plaintext data key. The last
# two have no readable field to keep, so their `Debug` prints a length
# and nothing else.
#
# `ResolvedCredential` joined them in the confirmation round. It is the
# entry in the cache a failed liveness probe exists to purge, it holds the
# upstream secret twice (once bare, once inside the header value), and it
# was `derive(Debug)` and `pub` with nothing formatting it, which is the
# state every leak in this file was in the day before something did.
